# Code generation reference

Use this reference when you need to regenerate arnmatch's AWS service and resource data or update mapping rules for newly released AWS resources.

Most users do not need to run code generation. Install the latest published package unless you are contributing new ARN patterns or mapping fixes.

## What codegen produces

The codegen pipeline converts AWS documentation and metadata into generated parser data:

```text
AWS Service Authorization Reference
CloudFormation resource specification
Resource Groups Tagging API supported-resource list
botocore service metadata
project rule files
        ↓
codegen/build/arn_patterns.yaml
        ↓
codegen/build/arn_patterns.py
        ↓
src/arnmatch/arn_patterns.py
```

The runtime parser imports `src/arnmatch/arn_patterns.py`. Do not edit this file directly; regenerate it from codegen inputs.

## Regenerate patterns

From the repository root, run:

```bash
make generate
make build
make check
```

These commands:

1. Rebuild `codegen/build/arn_patterns.yaml` and `codegen/build/arn_patterns.py`.
2. Copy the generated Python module to `src/arnmatch/arn_patterns.py`.
3. Build the package.
4. Run lint and tests.

You can also run the codegen pipeline directly:

```bash
cd codegen
make clean
make
```

Then return to the repository root and run:

```bash
make build
make check
```

## Refresh cached AWS metadata

The codegen pipeline keeps cache files in `codegen/cache/` so repeated runs are faster and reproducible. Refresh a cache when AWS has added services or resource types and the generated data looks stale.

### CloudFormation resource specification

To refresh the CloudFormation resource specification cache:

```bash
rm -f codegen/cache/CloudFormationResourceSpecification.json
make generate
```

This downloads the latest public CloudFormation resource specification during codegen.

### Resource Groups Tagging API supported resources

The Resource Groups Tagging API supported-resource list is fetched from AWS with a signed request. You need AWS credentials that can call the Resource Groups Tagging API endpoint.

Using an AWS profile:

```bash
rm -f codegen/cache/TaggingAPIResources.json
cd codegen
AWS_PROFILE=<profile> AWS_REGION=us-east-1 uv run index_tag.py
cd ..
```

Using environment variables:

```bash
rm -f codegen/cache/TaggingAPIResources.json
cd codegen
AWS_ACCESS_KEY_ID=<access-key-id> \
AWS_SECRET_ACCESS_KEY=<secret-access-key> \
AWS_SESSION_TOKEN=<session-token> \
AWS_REGION=us-east-1 \
uv run index_tag.py
cd ..
```

Then regenerate and verify:

```bash
make generate
make build
make check
```

`AWS_SESSION_TOKEN` is only required for temporary credentials.

## Understand missing mapping reports

During codegen, arnmatch tries to map each ARN resource type to CloudFormation and Resource Groups Tagging API resource types. If it cannot choose a reliable mapping, it writes a missing mapping report in `codegen/cache/`.

| Report | Meaning |
| --- | --- |
| `CloudFormationResourcesMissing.json` | ARN resource types that have candidate CloudFormation resources but no confident resource-level mapping. |
| `TaggingAPIResourcesMissing.json` | ARN resource types that have candidate Tagging API resources but no confident resource-level mapping. |

A missing entry is not always a bug. Many AWS resources are runtime operations, child resources, wildcard IAM policy resources, or newly released resources that are not exposed through CloudFormation or the Resource Groups Tagging API.

When a missing report is empty, codegen removes the stale report file.

## Choose overrides or excludes

For each missing entry, decide whether there is a real one-to-one mapping.

### Add an override when a mapping is reliable

Use an override when the ARN resource type clearly corresponds to a CloudFormation or Tagging API type, but automatic name matching cannot infer it.

CloudFormation resource mapping:

```json
{
  "s3express": {
    "bucket": "AWS::S3Express::DirectoryBucket"
  }
}
```

File:

```text
codegen/rules/cfn_resources_overrides.json
```

Tagging API resource mapping:

```json
{
  "aws-marketplace": {
    "Product": "AWS::MarketplaceCatalog::Entity"
  }
}
```

File:

```text
codegen/rules/tag_resources_overrides.json
```

### Add an exclude when no reliable mapping exists

Use an exclude when the resource does not have a distinct CloudFormation or Tagging API type, or when the ARN alone cannot identify one safely.

Common exclude cases:

- Async jobs, executions, sessions, and workflow runs.
- Child resources managed as properties of a parent resource.
- Wildcard IAM policy resource patterns such as “all listings”.
- Resources not returned by the Resource Groups Tagging API supported-resource list.
- Ambiguous resources where multiple candidate mappings are possible.

CloudFormation resource excludes:

```text
codegen/rules/cfn_resources_excludes.json
```

Tagging API resource excludes:

```text
codegen/rules/tag_resources_excludes.json
```

After changing overrides or excludes, run:

```bash
make generate
make build
make check
```

## Service-level mapping rules

Some fixes apply to services instead of individual resource types.

| Rule file | Use it for |
| --- | --- |
| `codegen/rules/sdk_overrides.json` | ARN services that map to a boto3 client with a different name. |
| `codegen/rules/sdk_excludes.json` | ARN services with no boto3 client. |
| `codegen/rules/cfn_overrides.json` | CloudFormation service names that map to a different ARN or SDK service name. |
| `codegen/rules/cfn_excludes.json` | CloudFormation services that should not be mapped. |
| `codegen/rules/tag_overrides.json` | Tagging API service names that map to a different SDK service name. |
| `codegen/rules/tag_excludes.json` | Tagging API services that should not be mapped. |

New AWS services sometimes appear in the Service Authorization Reference before botocore exposes a boto3 client. In that case, add the ARN service to `sdk_excludes.json` so the parser can still recognize the ARN while reporting no SDK client mapping.

## Verify generated behavior

After regeneration, test representative ARNs with the local package:

```bash
uv run arnmatch "arn:aws:lambda:us-east-1:123456789012:function:my-function"
```

For Python behavior:

```python
from arnmatch import arnmatch

resource = arnmatch("arn:aws:lambda:us-east-1:123456789012:function:my-function")
print(resource.resource_type)
print(resource.cloudformation_resource)
print(resource.tagging_resource)
print(resource.aws_sdk_service)
```

A successful codegen update should pass:

```bash
make check
```
